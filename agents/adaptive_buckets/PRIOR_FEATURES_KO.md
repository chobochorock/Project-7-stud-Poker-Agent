# prior 트리의 기본 특징 (일반 특징) 상세 (2026-11-11)

**문서 정보**
- 설계 문서 `PRIOR_POSTERIOR_DESIGN_KO.md` 7절의 세부다.
- 상태: 설계다. 구현하지 않았다.
- 숫자(칸 수, 특징 수)는 mini-stud small의 정보집합 51,114개를 분석 스크립트로 세어 확인한 값이다.

## 1. 원칙: 게임마다 다른 것은 어댑터 하나

```
정보집합 I ──(게임 어댑터)──▶ 관측 열 [(통로, 라운드, 순서, 기호), …] ──(공통 코드)──▶ 특징 F1–F4
```

- **게임 어댑터:** 정보집합을 "관측 열"로 바꾼다. 게임마다 다른 부분은 이것뿐이다.
- **공통 코드:** 관측 열에서 특징을 계산한다. 게임을 모른다.
- **특징의 이름:** 특징은 번호가 아니라 이름표(설명자)로 부른다. 예: `F2(개인 우연, K)`.
  - 트리는 이 이름표를 저장한다.
  - 그래서 나중에 새 칸이 생겨도(큰 게임에서 처음 보는 이력) 기존 트리가 흔들리지 않는다.

## 2. 관측 열의 정의

정보집합 = 그 플레이어가 지금까지 본 관측의 나열이다. 관측 하나는 네 값으로 이뤄진다.

| 값 | 뜻 | mini-stud에서의 값 |
|---|---|---|
| 통로 | 누가, 무엇을, 누가 볼 수 있게 했는가 | 아래 7가지 |
| 라운드 | 게임의 몇 번째 단계인가 | 0 = 처음 패와 선택, 1 = 5번째 카드와 베팅, 2 = 7번째 카드와 베팅 |
| 순서 | 그 라운드 안에서, 같은 종류(우연/행동)의 관측 중 몇 번째인가 | 0, 1, 2, … |
| 기호 | 관측된 값 | 카드 Q/K/A, 행동 f k c b d h, 모름 ? |

**통로 7가지** (모두 "나" 기준이다. 좌석 0/1이 아니다)

| 통로 | 뜻 | mini-stud에서 |
|---|---|---|
| 개인 우연 | 나만 본 우연 | 처음 숨은 패 3장, 7번째 숨은 카드 |
| 공개 우연·내 것 | 둘 다 본, 나에게 온 카드 | 5번째 공개 카드(내 것) |
| 공개 우연·상대 것 | 둘 다 본, 상대에게 온 카드 | 5번째 공개 카드(상대 것) |
| 상대 숨은 우연 | 상대가 받은 것은 알지만 기호는 모름 | 상대의 7번째 숨은 카드(?) |
| 내 비공개 행동 | 나만 아는 내 행동 | 버린 카드 |
| 내 공개 행동 | 상대도 본 내 행동 | 공개한 카드, 내 베팅 행동 |
| 상대 공개 행동 | 내가 본 상대 행동 | 상대가 공개한 카드, 상대 베팅 행동 |

- **공용 공개 우연**(홀덤의 보드 카드처럼 누구의 것도 아닌 카드)은 일반 게임용으로 정의만 해 둔다. stud에는 없다.
- **좌석**(내가 0번인지 1번인지)은 관측과 별도로 특징 F4에 넣는다.
- mini-stud small에서 버림과 공개는 휴리스틱 규칙이 정하므로 결정 노드는 아니다. 하지만 정보집합에 기록되는 관측이므로 그대로 넣는다.

## 3. mini-stud 어댑터: 키 → 관측 열

**키의 형식:** `p좌석|h처음패|d버림|r공개|o상대공개|s0:내5번째/상대5번째|s1:내7번째*/?|b베팅…`
- 베팅은 (스트리트, 행동자, 행동 코드) 세 글자씩이다.

| 키 부분 | 관측 (통로, 라운드, 순서, 기호) |
|---|---|
| `h` 세 글자 | (개인 우연, 0, 0–2, 각 숫자). 처음 패는 순서 없는 묶음으로 나눠지므로 정렬된 순서를 쓴다 |
| `d` | (내 비공개 행동, 0, ·, 숫자) |
| `r` | (내 공개 행동, 0, ·, 숫자) |
| `o` | (상대 공개 행동, 0, ·, 숫자) |
| `s0:X/Y` | (공개 우연·내 것, 1, ·, X), (공개 우연·상대 것, 1, ·, Y) |
| `s1:X*/?` | (개인 우연, 2, ·, X), (상대 숨은 우연, 2, ·, ?) |
| 베팅 `s a c` | 행동자가 나이면 (내 공개 행동, s+1, ·, c), 상대이면 (상대 공개 행동, s+1, ·, c) |

- 순서(·)는 그 라운드에서 같은 종류의 관측을 센 번호다.
- 베팅은 나와 상대가 순서 번호를 함께 쓴다. 그래서 행동이 끼어든 순서가 그대로 남는다.

## 4. 특징 네 가족

### F1 완전 부호화: (통로, 라운드, 순서) 칸마다 기호를 0/1로 표시

- 칸이 비어 있으면(아직 일어나지 않음) 그 칸의 특징은 모두 0이다.
- mini-stud small: **칸 19개, 0/1 특징 55개.** 실제로 나타나는 (칸, 기호) 조합만 만든다.

| 칸 (통로, 라운드, 순서) | 나타나는 기호 |
|---|---|
| (개인 우연, 0, 0), (개인 우연, 0, 1), (개인 우연, 0, 2) | Q K A |
| (내 비공개 행동, 0, 0) | Q K A |
| (내 공개 행동, 0, 1), (상대 공개 행동, 0, 2) | Q K A |
| (공개 우연·내 것, 1, 0), (공개 우연·상대 것, 1, 1) | Q K A |
| (개인 우연, 2, 0) | Q K A |
| (상대 숨은 우연, 2, 1) | ? |
| (내/상대 공개 행동, 1, 0) | k b h |
| (내/상대 공개 행동, 1, 1) | k c b d h |
| (내/상대 공개 행동, 1, 2) | c |
| (내/상대 공개 행동, 2, 0) | k b h |
| (상대 공개 행동, 2, 1) | b d h |

- F1과 좌석(F4)만으로 정보집합 51,114개가 모두 구분된다(스크립트로 확인함). 그래서 트리가 원리적으로 정보집합 하나까지 가를 수 있다.

### F2 통로별 기호 개수 (관측 주머니): 위치를 지우고 센다

- (통로, 기호)마다 그 기호가 몇 번 나왔는지 센다. 라운드와 순서는 무시한다.
- 추가로 모든 우연 통로를 합쳐서도 센다. "내가 본 K가 모두 몇 장인가"를 뜻한다. 상대의 공개 카드까지 포함하므로, 죽은 카드를 세는 효과가 있다.
- mini-stud small: (통로, 기호) 29개 + 우연 합계 3개 = **32개.**

### F3 라운드별 행동

- (라운드, 행동자 나/상대, 행동 기호)마다 횟수: 17개
- 라운드마다 전체 행동 수: 2개
- 각 플레이어의 마지막 행동(기호 0/1): 나 5개 + 상대 5개
- 합계 약 **29개.**

### F4 길이와 위치

- 좌석, 전체 관측 수, 우연 관측 수, 지금 라운드 번호, 지금 라운드의 행동 수: **5개.**

**합계: mini-stud small에서 약 121개.** 분할할 때만 전부 계산한다.

## 5. 예시

**키:** `p0|hQQK|dK|rQ|oA|s0:Q/K|s1:A*/?|b00k01b00c10b11d`
- 이 키는 실제 게임 트리에 있다.
- 지금 7번째 베팅 차례이고, 합법 행동은 폴드/콜/따당/하프다.

**관측 열:**
```
(개인 우연,0,0,Q) (개인 우연,0,1,Q) (개인 우연,0,2,K)
(내 비공개 행동,0,0,K) (내 공개 행동,0,1,Q) (상대 공개 행동,0,2,A)
(공개 우연·내 것,1,0,Q) (공개 우연·상대 것,1,1,K)
(개인 우연,2,0,A) (상대 숨은 우연,2,1,?)
(내 공개 행동,1,0,k) (상대 공개 행동,1,1,b) (내 공개 행동,1,2,c)
(내 공개 행동,2,0,b) (상대 공개 행동,2,1,d)
```

**특징 일부:**
- **F1:**
  - (개인 우연,0,0)=Q → 1
  - (상대 공개 행동,2,1)=d → 1
  - 나머지 해당 칸도 1이고, 그 외는 0이다.
- **F2:**
  - 개인 우연: Q 2, K 1, A 1
  - 공개 우연·내 것: Q 1. 공개 우연·상대 것: K 1. 상대 숨은 우연: ? 1
  - 내 비공개 행동: K 1
  - 내 공개 행동: Q 1, k 1, c 1, b 1
  - 상대 공개 행동: A 1, b 1, d 1
  - 우연 합계: Q 3, K 2, A 1
- **F3:**
  - 라운드 1: 나 k 1·c 1, 상대 b 1, 합 3
  - 라운드 2: 나 b 1, 상대 d 1, 합 2
  - 마지막 행동: 나 b, 상대 d
- **F4:** 좌석 0, 관측 15, 우연 관측 7, 라운드 2, 이번 라운드 행동 2.

**트리 검사의 예**
- `F2(개인 우연, K) ≥ 1`: 처음 패나 7번째 숨은 카드에 K가 있는가.
- `F3(라운드 2, 상대, d) ≥ 1`: 상대가 이번 스트리트에 따당을 했는가.
- `F1(공개 우연·상대 것, 1, 1) = A`: 상대의 5번째 공개 카드가 A인가.

## 6. 일반 특징으로 한 번에 나오지 않는 것 (한계)

**"지금 가진 패"가 한 번에 나오지 않는다.**
- 지금 가진 패 = 개인 우연 − 버린 카드 + 공개 우연·내 것이다. 위 예에서는 Q 3장, A 1장이다.
- 두 통로의 차이라서, 일반 특징으로는 트리 검사 여러 번을 거쳐야 표현된다.
  - "버림"이 패에서 카드를 뺀다는 것은 포커의 뜻이지, 일반 게임의 뜻이 아니기 때문이다.

**족보 구조와 칩 크기도 일반 특징에 없다.**
- 족보 구조: 같은 숫자의 최대 개수, 페어 수.
- 칩 크기: 팟 크기.

**포커 전용 옵션 `--features poker`는 다음을 더한다.**
- 지금 가진 패의 숫자별 개수(내 전체, 내 공개)
- 같은 숫자의 최대 개수, 페어 수
- 팟 크기(ante 단위)

**이 옵션의 쓰임**
- 일반 특징만으로 얼마나 잃는지를 비교한다.
- 비교의 뜻: 일반 특징으로 충분하면, 방법이 게임 지식 없이 돈다는 주장의 근거가 된다.

## 7. 분할 때와 학습 때

**분할 때** (prior 칸 하나를 나눌 때만)
- 그 칸의 정보집합(작은 게임은 전부, 큰 게임은 표본)을 관측 열로 바꾼다.
- F1–F4를 모두 계산해 표를 만든다. 예: mini-stud에서 칸 하나가 1만 개 정보집합이면 121 × 1만이다.
- 트리 검사를 고른 뒤 표를 버린다. 사용자의 "분할 때만 메모리" 안이다.

**학습 때**
- 정보집합의 prior 잎을 찾으려고 트리를 내려갈 때, 지나는 검사의 특징만 계산한다(관측 열에서 바로 센다).
  - 깊이가 d이면 특징 d개다.
- 비용이 문제가 되면 "정보집합 → 관측 열" 해석 결과를 캐시하는 옵션을 둔다. 동일성 시험을 통과해야 쓴다.
- 분할마다 트리와 쓴 특징의 이름표 목록을 `prior_tree_K.json`에 저장해 보고한다.

## 8. 7-stud로 갈 때 바뀌는 것

**새 어댑터**
- 7-stud 정보집합 → 관측 열. 라운드 5개, 행동 종류가 더 많다.

**기호에 속성이 생긴다**
- 카드 기호가 52가지이고, 속성(숫자, 무늬)을 가진다.
- F2를 기호별 + 속성값별로 센다(숫자별 개수, 무늬별 개수).
  - 이것도 게임 지식이 아니라 "기호의 속성"이라는 일반 개념이다. 어댑터가 속성을 알려 주면 공통 코드가 센다.

**특징 수**
- F1이 수천 개로 늘어난다.
- 분할할 때 표본 수 × 특징 수의 표가 필요하지만, 학습 중에는 여전히 경로 위의 특징만 계산한다.
