# 7-stud SOTA 대조군 (2026-11-05 시작)

ASWISS·k-means와 **같은 게임**(heads-up, 규칙 v3, 5구부터, heuristic H4), **같은 실행 파일**(`../aswiss_stud.cpp`), **같은 평가**(Policy-LBR deal·seed·particle, BR-gap 근사치 deal), **같은 시간 기록**(`log.csv`·`curve.csv`·`snapshots.csv`)으로 비교하려고 만든 신경망 대조군이다. 외부 라이브러리는 쓰지 않는다(torch 없음). 그래서 노트북에서도 추가로 설치할 것이 없다.

## 고른 대조군과 진행 상태

**기본 대조군 (2026-11-05 결정): ReBeL, MMD, ESCHER.** 계열마다 대표를 하나씩 둔다.

| 계열 | 방법 | 한 번 방문이 다른 정보집합을 바꾸는 방식 | 상태 |
|---|---|---|---|
| 정책 기울기 | **MMD 자기대전** (Sokota 외 ICLR 2023; Rudolph 외 ICLR 2026에서 가장 강했던 계열) | 공유 정책망 | 구현·검증·조율 끝 |
| 신경망 CFR | **ESCHER** (McAleer 외 ICLR 2023) | 후회망 | 구현·검증 끝 |
| 학습 + 탐색 | **ReBeL** (Brown 외 NeurIPS 2020), CPU 축소판 | 가치망, 그리고 두는 순간 하위 게임을 직접 푼다 | 구현·검증 끝, 학습 곡선 확인 중 |

**Obscuro (Zhang & Sandholm, arXiv 2506.01242)는 넣지 않는다.** 원문을 확인한 근거는 다음과 같다.
- **풀려는 문제가 다르다.** Fog of War 체스처럼 공통 지식 집합이 10¹⁸ 규모라 나열할 수 없는 게임을 위한 탐색이다(KLUSS, 한쪽 GT-CFR + PCFR+). 원문은 heads-up 포커가 공통 지식 집합이 작아 포커 전용 하위 게임 풀이로 충분하다고 대비시킨다. 7-stud는 포커 쪽이라, 탐색 계열 대표로는 ReBeL이 맞다.
- **잎 평가 함수가 필요하다.** 원문은 Stockfish의 완전정보 평가를 썼고, 평가 함수를 약하게 바꾸자 성능이 크게 떨어졌다. 7-stud에는 그런 평가 함수가 없다. 학습한 가치망을 쓰면 ReBeL과 겹친다. 원문도 학습한 평가 함수와의 결합을 향후 과제로 남겼다.

## 파일

- `nn.hpp`: 두 은닉층 MLP(ReLU), 희소 첫 층(켜진 입력의 열만 더함), Adam(첫 층은 배치가 건드린 행만 갱신), 저장·불러오기. 기울기 검사 통과(상대 오차 2e-4, float 정밀도).
- `mmd.hpp`, `escher.hpp`: 게임과 무관한 MMD, ESCHER. 같은 코드를 7-stud와 내보낸 트리(`../../compare/nn_tree.cpp`, `--algo mmd|escher`)에서 쓴다.
- `stud7_net.hpp`, `stud7_net_main.hpp`: 7-stud 연결. `train --partition net --algo mmd|escher`, `eval --partition net`.
- `rebel.hpp`, `rebel_main.hpp`: 7-stud 전용 ReBeL 축소판. `train --partition rebel`, `eval --partition rebel`.

## MMD 구현

- 갱신마다 현재 정책으로 자기대전 `--mmd-episodes`판을 모은다. 두 좌석이 같은 망을 쓰고, 좌석은 입력에 들어 있다.
- 손실 (합법 행동에 대해 정확한 KL, 원문 부록 L 40쪽의 심층 MMD 손실과 같다):
  L(θ) = E[−(π_θ(a|x)/π_old(a|x))·Â] + α_t·KL(π_θ ‖ magnet) + β_t·KL(π_θ ‖ π_old)
  - Â: 할인 수익 − 가치망 추정, 배치마다 정규화. 할인 수익 = γ^k × 최종 이득(k = 그 좌석의 이후 결정 수, `--mmd-gamma`).
  - `--mmd-clip ε`(> 0): 비율 항을 PPO의 클리핑 대리 목표 min(rÂ, clip(r, 1−ε, 1+ε)Â)로 바꾼다.
  - 일정 `--mmd-schedule sqrt`: α_t = α0·√(H/t), β_t = 1/η_t, η_t = η0·√(H/t), t = 지금까지의 결정 표본 수(원문 37쪽, 환경 스텝). `const`면 α, β가 상수다.
  - magnet: 기본은 균등 분포다. `--mmd-magnet-every K`면 K갱신마다 현재 정책으로 옮긴다(R-NaD식, 원문의 이동 magnet과는 다르다).
  - 가치망은 수익/`--mmd-reward-scale`(기본 10)을 회귀한다.
- 입력: 엔진의 Deep CFR 정보상태 텐서(`deep_cfr_tensor`, 1,832차원 one-hot)다. 내 숨은·보인 카드, 상대 보인 카드, 내가 버린 카드, 베팅 이력 24칸, 팟 정보, 합법 행동이 들어 있다.
- **기본값 (7-stud, 2026-11-06 개정):** 원문의 심층 다중 에이전트 설정(부록 J, 37쪽 = RLlib PPO 기본값에 MMD의 KL 항과 일정)을 따른다.
  - 갱신당 1,000판(약 4,000 결정 = RLlib의 4,000 스텝), 30 epoch × 미니배치 128, 학습률 5e-5(가치망도), 클리핑 0.3, γ=0.99, α0 = η0 = 0.05, H = 1천만.
  - 은닉 512×512(공개된 원문 체크포인트의 크기, 정책망 파라미터 1,205,256개). 활성 함수는 ReLU다(원문 tanh).
  - 그 밖의 차이: 합법 행동을 마스킹한다(원문 환경은 불법 행동에 벌점). 정책과 가치망의 최적화기가 따로다. 가치 손실 클리핑(RLlib 10)이 없다.
  - 이전 기본값(2026-11-05): 은닉 128×64, 갱신당 2,048판, 2 epoch × 512, 학습률 3e-4, α=0.2·β=1 상수, 클리핑·할인 없음.
- 평가: MMD가 보장하는 것은 마지막 반복이라, 신경망은 **현재 정책 하나만** 평가한다. 같은 값을 평균 정책으로 복사하지 않는다(`evaluate.py`가 `partition net`이면 현재 정책만 돌린다).
- 1 root = 표본으로 뽑은 5구 root에서 시작한 자기대전 한 판이다. 스냅숏은 epoch 경계(1만 roots에서 두 배씩)를 넘은 첫 갱신에서 찍으므로, roots가 최대 2,047만큼 늦을 수 있다.

## ESCHER 구현

원문(McAleer 외 ICLR 2023)의 구성을 따른다.
- **역사 가치망:** 두 좌석의 정보상태 텐서를 이어 붙인 전체 역사(3,664차원)에서 좌석 0의 수익/`--escher-reward-scale`을 회귀한다. 반복마다 `--escher-value-hands`판을 현재 정책(결정마다 확률 `--escher-value-explore`로 균등 행동)으로 두고, 그 반복의 데이터로만 학습한다. `--escher-value-reinit 1`(기본)이면 반복마다 새로 초기화한다(공식 코드 기본값).
- **후회 표본:** 반복마다 좌석별로 `--escher-traversals`판을 순회한다. 순회 좌석은 균등 표본 정책으로 행동 하나를 고른다(중요도 가중치 없음). 그 노드의 모든 합법 행동 a에 대해 r(a) = V(h·a) − Σ_b σ(b)·V(h·b)를 저장한다. 상대는 σ를 따르고, 그 노드의 σ를 평균 정책 표본으로 저장한다.
- **후회망:** 좌석별로 반복마다 처음부터 다시 학습한다(`--escher-reinit 1`). 저수지 표본에 가중치 t'/t를 주고 `--escher-regret-steps`번 학습한다. 현재 정책은 예측 후회의 양수 부분으로 regret matching한 것이다. 양수가 없으면 예측 후회가 가장 큰 행동을 둔다(`--escher-fallback argmax`, Deep CFR과 공식 코드; `uniform`은 이전 방식).
- **평균 정책망:** 스냅숏마다 전략 저수지로 처음부터 학습한다(가중 교차 엔트로피, 가중치 t). 자기 난수를 써서, 스냅숏을 찍어도 학습이 바뀌지 않는다.

**2026-11-06 개정:** 기본값을 원문 표 3과 18쪽, 그리고 원문이 정하지 않은 곳은 공식 코드 기본값으로 바꿨다. 원문·공식 코드와 대조한 전체 목록은 "원문·공식 코드 대조" 절에 있다.
- 남은 차이: 가치망 데이터의 탐색 보정 방식(공식 코드는 중요도 비율로 목표를 보정, 이쪽은 마지막 탐색 행동 이후의 역사만 사용; 기댓값은 같다), 활성 함수(ReLU, 공식 코드 LeakyReLU + LayerNorm), 평균 정책 손실(교차 엔트로피, 공식 코드 MSE).

아래는 이전 설정(2026-11-05)에서 원문과 다르게 두었던 점과 그 근거다. 탐색 0.25는 원문 값 0.01과 비교한 것이 아니라 탐색 0과 비교한 것이었다.
- **가치망 학습 표본에 탐색을 넣었다** (이전 `--escher-value-explore 0.25`, 지금 기본 0.01). 결정마다 확률 0.25로 균등 행동을 두고, 그 손의 마지막 탐색 행동 뒤의 역사만 학습에 쓴다. 그 뒤는 σ를 따랐으므로 수익이 그 역사의 v_σ 표본이다.
  - 넣은 이유: 현재 정책으로만 모으면 σ가 거의 두지 않는 행동 뒤의 값을 배우지 못하는데, 후회 계산은 모든 행동 뒤의 값을 쓴다.
  - Kuhn에서 평균 정책이 2.5만 판에 0.075(탐색 없음 0.345)로 더 빨리 내려갔다. Leduc 79만 판에서는 1.07이었다(탐색 없음 1.19).
- **후회 목표를 reward scale 단위로 저장한다.** regret matching은 크기에 무관하다. 7-stud(scale 10)에서 망이 수십 칩 단위 목표를 처음부터 맞추느라 손실이 수천이던 문제를 없앴다.

**7-stud 기본값 (2026-11-06 개정):** 원문 표 3 — 반복마다 가치 1,000판 + 좌석별 순회 1,000판(= 3,000 roots), 배치 2048, 후회 학습 5,000스텝, 가치 학습 5,000스텝, 평균망 학습 10,000스텝; 원문 18쪽 — 가치 데이터 탐색 0.01; 공식 코드 기본값 — 은닉 256×128, 학습률 1e-3, 저수지 각 10만, 반복마다 가치망 재초기화, argmax 대체. scale 10.
- 이전 기본값(2026-11-05): 은닉 128×64, 가치 4,096판 + 순회 8,192판×2, 후회 300·가치 200·평균 2,000스텝, 배치 512, 저수지 50만, 탐색 0.25, 가치망 이어서 학습, 균등 대체.

**평가:** 평균 정책(평균망)과 현재 정책(후회망 regret matching)을 따로 평가한다(`evaluate.py`가 `net_kind.txt`로 구별).

**검증:**
- 재개: 7-stud ESCHER를 STOP으로 멈춘 뒤 이은 실행이 끊지 않은 실행과 스냅숏 3개, log, curve가 바이트 단위로 같았다.
- 표 기반 경로 불변: 새 실행 파일의 `hist_bbf` 7만 roots가 이전 실행 파일과 스냅숏, log, backward, fill이 바이트 단위로 같았다.
- Kuhn (1,024반복, 은닉 64×32): 평균 정책 0.50 → 39만–157만 판에 0.076–0.087, 현재 정책 0.13–0.29.
- Leduc (256반복, 반복마다 가치 1,024판 + 순회 1,024판×2): 평균 정책 2.88 → 79만 판에 1.07, 현재 정책 1.55–2.0. 같은 판 수의 MMD(0.47)보다 나쁘다. 가치망 오차(제곱 오차 6–14)가 후회 표본의 잡음으로 들어가기 때문으로 본다.

## ReBeL 축소판

ReBeL(Brown 외 NeurIPS 2020)의 뼈대를 7-stud v3와 CPU 한 코어에 맞춰 줄였다. 저장소의 이전 시도(`../../../../cpp_mccfr/REBEL_*.md`)는 30M MCCFR blueprint로 믿음을 재구성했고 Python/TorchScript 가치 서버가 필요했다. 6구 탐색 + 7구 해결기로 LBR 1.24 ante/hand였다. 이 구현은 blueprint 없이 처음부터 자기대전으로 학습하고, 외부 라이브러리 없이 C++만 쓴다.

**ReBeL에서 그대로 가져온 것:**
- **공개 믿음 상태(PBS):** 두 좌석의 사적 카드 범위다. 관측한 행동마다 탐색 정책의 확률로 베이즈 갱신한다. 상대 카드와 겹치는 조합은 정확히 뺀다(포함–배제).
- **깊이 제한 하위 게임:** 베팅 라운드 하나(한 street)다.
- **가치망:** PBS를 받아 두 좌석의 모든 사적 손에 대한 값을 낸다. 입력은 공개 카드, 팟, 두 범위(1,326칸씩)이고, 출력은 두 좌석 × 1,326칸(값/팟)이다.
- **자기대전 데이터 생성:** 판마다 한 좌석을 골라 그 좌석의 결정에서 확률 ε=0.25로 균등 행동을 둔다(원문 15·18쪽; 2026-11-06 개정, 이전에는 두 좌석 모두 ε=0.1). 각 street 뿌리의 PBS와 그 탐색 값을 학습 표본으로 쓴다.
- **임의 반복 (2026-11-06 개정):** 5구·6구에서는 CFR 반복 t를 평균 가중치(t²)에 비례해 하나 뽑아, 그 반복의 정책으로 두고 그 정책으로 믿음을 갱신한다(원문 알고리즘 1, 정리 3). 이전에는 평균 전략으로 두었다(원문 7쪽이 말하는 "안전하지 않은 탐색"). 7구는 잎 가치가 없는 마지막 하위 게임이라 평균 전략으로 둔다.
- **가치망 손실:** 점별 Huber(δ=1, 원문 8쪽; 이전에는 MSE). `log.csv`의 손실 열은 비교를 위해 계속 제곱 오차다.
- **시험 때도 같은 탐색을 쓴다.** 임의 반복은 공개 이력과 시드로 정해지는 난수로 뽑아, 같은 공개 상태를 다시 풀어도 같은 반복을 쓴다. Policy-LBR은 뽑힌 반복의 정책을 본다(공격자가 시드를 아는 셈이다; 원문의 정리는 상대가 모른다고 가정한다). `eval --rebel-play average`로 평균 전략 평가도 할 수 있다.

**줄이거나 근사한 것:**
1. **사적 타입은 3구의 숨은 두 장(쌍)이다.** H4 버림 카드는 주변화했다.
   - 상대의 버림 카드는 모르는 죽은 카드로 보고, 자기 버림 카드는 탐색 정보에 넣지 않는다.
   - 초기 범위는 휴리스틱 H4가 그 공개 카드를 보여 줄 (배분 순서, 버림 카드) 조합 수다.
2. **5구·6구:** 모든 쌍(약 1,000개)에 대해 정확한 벡터 CFR을 돌린다(DCFR 1.5/0/2, 동시 갱신, 32반복). street 끝의 잎(5구 16개, 6구 124개)마다 가치망을 부른다.
   - CFR-D처럼 잎의 PBS는 현재 반복의 범위로 만든다.
   - 가치망은 다음 street 카드를 나누기 **전**의 값을 낸다. 학습 목표는 표본 한 번으로 나눈 뒤의 다음 street 뿌리 값이다(카드 제거 효과로 인한 작은 편향이 있다).
3. **7구:** 쇼다운까지 푼다(가치망 없음). 7구 타입(쌍 + 7구 숨은 카드, 약 4만 개)과 베팅 트리(결정 노드 1,097개)가 커서 정확한 범위 CFR은 불가능하다.
   - 그래서 좌석마다 타입을 범위 질량의 **족보 강도 분위수 64개 버킷**으로 묶는다.
   - 버킷 게임의 확률 행렬은 정확한 카드 호환 범위로 만든다. 그 위에서 DCFR을 64반복 돌린다.
   - 한 타입의 값과 정책은 그 버킷의 것을 쓴다. 버킷 안의 카드 제거 차이는 무시한다.
4. **탐색은 street마다 한 번이다.** street 안에서 상대가 행동한 뒤 다시 풀지 않는다.
   - 정책망 warm start가 없다.
   - CFR 반복 수와 망 크기가 작다(은닉 128×128, 두 망 합계 142만 파라미터).
   - 재생 버퍼는 망마다 FIFO 4,096개다. 한 판마다 망별로 배치 32의 Adam 4스텝을 학습한다(`--rebel-train-steps`, 학습률 3e-4).

**평가:**
- 같은 Policy-LBR deal과 particle 수를 쓴다.
- LBR의 particle 난수는 pair마다 seed를 따로 준다. 그래서 `--threads`를 바꿔도 결과가 같고, 다른 비교군과는 deal만 같다.
- BR-gap 근사치는 계산하지 않는다(NaN). gap 순회가 지나는 모든 공개 상태마다 탐색해야 하기 때문이다.
- 평가 정책은 탐색 정책 하나이고, 그림에서는 현재 정책 패널에 그린다.
- "roots"는 자기대전 판 수다. 한 판이 street 하위 게임을 최대 셋 푸므로, 다른 비교군과의 비교는 벽시계 축으로 한다.

세 원문 PDF(MMD arXiv 2206.05825v4, ESCHER 2206.04122v2, ReBeL 2007.13544v2)와 공식 저장소(`ssokota/mmd` 0505c94, `Sandholm-Lab/escher` e694eaa, `facebookresearch/rebel` 7960a42)를 우리 구현과 항목별로 대조했다. 쪽 번호는 PDF 쪽이다.

**판정 요약:**
- **MMD:** 손실식은 원문 부록 L(40쪽)의 심층 MMD 손실과 같다(두 KL의 방향도 같다). 그러나 원문의 심층 실험은 RLlib PPO를 고친 것이고, α와 η를 줄여 가는 일정을 썼다(37쪽). 우리는 둘 다 상수다. Leduc 검증값이 원문 참고값보다 분명히 나쁘다.
- **ESCHER:** 후회 추정식은 원문 식 7(6쪽 알고리즘 2)과 같다. 공식 코드의 기본값(`importance_sampling=True`)은 원문의 절제 실험 2(도달 확률 가중)라서, 우리가 오히려 원문에 더 가깝다. 그러나 가치망 탐색 비율(원문 0.01, 우리 0.25), 가치망 재초기화, 반복당 학습량이 다르다. 원문에는 심층 ESCHER의 Kuhn·Leduc 수치가 없어 검증값을 직접 맞대 볼 수 없다.
- **ReBeL:** 두 가지가 원문의 보장을 깬다. (1) 임의 반복 정책 대신 평균 전략으로 두고 믿음을 넘긴다(원문 7쪽이 "안전하지 않은 탐색"이라 부르는 것). (2) 7구를 64버킷 카드 추상화로 푼다. (1)은 계산 비용 없이 고칠 수 있다.

| CFR | 교대 갱신 Linear CFR, HUNL은 변형 CFR-AVG(8–9쪽). Liar's Dice 1,024반복 | DCFR 동시 갱신, 32/64반복 | 규모 |
| 가치망 | HUNL 6×1536 GeLU+LayerNorm, Huber, 버퍼 1,200만, 1,750 epoch × 256만 표본(18쪽) | 2×128 ReLU 두 개, MSE, 버퍼 4,096 | 규모 |
| 계산 | HUNL 데이터 생성: DGX-1 90대 × V100 8장 = GPU 720장. Liar's Dice: GPU 1장 + CPU 60스레드(18쪽) | 1코어 | 규모 |

**고칠 것 (우선순위):**
1. MMD: 원문의 α·η 일정(그리고 선택적으로 클리핑 0.3). 공식 표 기반 MMD를 우리 Kuhn·Leduc 트리에 옮겨 그림 20의 바닥(Kuhn 약 0.044, Leduc 약 0.084)을 재현하고, 심층 MMD를 그림 15와 seed 3개 이상으로 맞대 본다.
2. ESCHER: 가치망 탐색 0.01, 반복마다 가치망 재초기화, 원문 표 3·4 수준의 학습량(또는 Leduc에서 더 늘려도 같음을 보임). 공식 코드(`importance_sampling=False`, `val_expl=0.01`)로 Kuhn·Leduc 기준 실행을 seed 3개 이상 돌려 우리 구현과 비교한다.
3. ReBeL: 임의 반복 표본(학습과 시험), ε=0.25 한 좌석. 7구 추상화와 버림 카드 무시는 논문에 밝히고, 본문 SOTA 비교가 아닌 부록의 축소판으로 둔다.
4. 모든 비교군 seed 3개 이상.

## 비용 (이 컨테이너, 4코어 중 1코어)

| 비교군 | 학습 속도 | 노트북 실행 예산 | 평가 (Policy-LBR) |
|---|---|---|---|
| MMD | 갱신 1번(2,048판)에 약 0.6초, 초당 약 3,400 roots | 1억 roots ≈ 8시간 | 2,000 pair 약 1분, 20,000 pair 약 10분 |
| ESCHER | 반복 1번(20,480 roots)에 약 24초, 초당 약 850 roots | 1억 roots ≈ 30시간. 언제든 STOP하고 그때까지의 곡선을 쓸 수 있다 | MMD와 같다 (정책이 둘이라 2배) |
| ReBeL | 한 판에 약 1.4–1.7초(다른 작업과 함께 돌 때). 거리별 탐색은 5구 0.08초, 6구 0.5초, 7구 1.15초이고, 망 학습 4스텝이 약 0.2초다 | 6만 판 ≈ 23–28시간(표 기반 1억 roots보다 조금 길다). 언제든 STOP해도 그때까지의 곡선을 쓸 수 있다 | 한 pair에 약 2.3–2.9 스레드·초: 2,000 pair가 4스레드로 약 20–25분, 20,000 pair가 4스레드로 약 3–4시간 |

- MMD의 이전 설정(은닉 256×128, 학습 반복 4회)은 갱신당 5.2초로 9배 느렸다.
- 노트북 시간은 코어 속도와 동시 실행 수에 따라 다르다. 벽시계 비교에는 실행 순서와 동시 실행 수를 함께 적는다.

## 실행

```powershell
# 다른 비교군과 같은 폴더, 같은 seed. mmd·escher는 같은 roots(1억), rebel은 자기 예산(6만 판)
powershell -ExecutionPolicy Bypass -File agents\adaptive_buckets\aswiss\stud7\run_100m.ps1 -Arms mmd,escher,rebel -SnapshotEvery 0
powershell -ExecutionPolicy Bypass -File agents\adaptive_buckets\aswiss\stud7\run_100m.ps1 -Arms mmd,escher,rebel -Action status
powershell -ExecutionPolicy Bypass -File agents\adaptive_buckets\aswiss\stud7\run_100m.ps1 -Arms mmd,escher,rebel -Action eval
```

- 세 비교군은 각각 한 코어를 쓴다. 이미 끝난 표 기반 비교군과 시간을 견줄 때는 동시 실행 수를 기록해 둔다.
- `-Action stop`은 STOP 파일을 쓴다. ReBeL은 다음 판이 끝나면 checkpoint를 남기고 멈춘다. 같은 명령으로 비트 단위로 이어진다.
- `-Action eval`·`final`에서 ReBeL은 `-Workers`개 스레드로 LBR 판을 나눠 돈다. `--min-roots`는 ReBeL에 적용하지 않는다.
- `-Action plot`에 `mmd`, `escher`, `rebel`을 넣으면 다음처럼 그려진다.
  - MMD와 ReBeL은 현재 정책 패널에만 그려진다.
  - ESCHER는 두 패널 모두에 그려진다.
  - bucket 패널에는 파라미터 수가 찍힌다.
- 시간 비교는 `plot_stud_time.py`로 한다(`../README_KO.md`의 "학습 시간").
- 온라인 LBR(학습 중 test-then-train 지표)은 `-OnlineLbrEvery 1000`으로 켠다(ReBeL은 10판마다). 설명과 검증은 `../README_KO.md`의 "온라인 LBR" 절에 있다. ESCHER는 감시용 평균망(반복마다 전략 저수지로 이어 학습, 시간은 평가 시간으로 뺀다), MMD는 마지막 반복 정책, ReBeL은 탐색 정책을 잰다.
- 하이퍼파라미터는 `--mmd-*`, `--escher-*`, `--rebel-*` 옵션으로 바꾼다. 바꾸면 checkpoint 설정이 달라지므로 새 출력 폴더가 필요하다.

## GPU 실험 계획 (노트북 RTX 5060, CPU 실험 다음)

**질문:** GPU를 쓸 수 있는 비교군이 GPU를 썼을 때도, ASWISS(CPU)와의 "학습 시간 대비 성능" 관계가 유지되는가.

**대상 알고리즘:**

| 알고리즘 | GPU가 돕는 부분 | GPU 이점을 보려면 |
|---|---|---|
| MMD | 자기대전 배치 추론, 큰 배치 학습 | 망(예: 512×512)과 갱신당 판 수를 키운다. 지금 크기(128×64)는 실행 지연이 커서 이득이 작을 수 있다 |
| ESCHER | 가치·후회·평균망 학습(지금 시간의 대부분), 순회의 망 호출 | 망 호출을 여러 판 묶어 배치로 부른다 |
| ReBeL | 5·6구 벡터 CFR과 잎 가치망(원 구현도 GPU 텐서 연산), 7구 버킷 게임의 행렬곱 | 가치망을 키우고(원 논문은 훨씬 큰 망), 풀이 전체를 텐서로 옮긴다 |
| (후보) Deep CFR | 저장소의 `cpp_mccfr/train_deep_cfr_7th.py` (C++ 순회 + PyTorch, TCP) | `--device cuda`로 바로 돌릴 수 있으나 평가 경로를 맞춰야 한다 |

- 표 기반(ASWISS, k-means)은 해시 표와 표본 순회라 GPU 이점이 없다. 지금처럼 CPU 코어 하나로 둔다.

**구조:**
- 규칙, 딜, 특징, LBR은 지금의 C++ 엔진을 그대로 쓴다.
- 학습과 배치 추론만 PyTorch(GPU)로 옮긴다.
- 둘 사이는 C API 공유 라이브러리(ctypes)나, 저장소에 이미 있는 배치 TCP 방식으로 잇는다.
- 학습한 망은 지금과 같은 스냅숏 형식(`STUDNET1`, `STUDESC1`, `STUDRBL1`)으로 내보낸다. 그러면 오프라인·온라인 LBR이 CPU 실행과 같은 C++ 평가기로 계산된다.

**변인 통제:**
- 비교군마다 쓴 하드웨어를 함께 적는다. 표 기반은 CPU 코어 1개, GPU 비교군은 CPU 코어 1개 + GPU다.
- GPU 비교군은 한 번에 하나씩 돌린다. VRAM 8GB를 나눠 쓰면 시간이 섞이기 때문이다.
- 게임, seed, deal, 온라인 LBR(16파티클), 오프라인 LBR(64파티클)은 CPU 실험과 같다.
- 같은 알고리즘의 CPU판과 GPU판을 나란히 두면 GPU의 효과만 따로 볼 수 있다.
- 원하면 GPU 전력(`nvidia-smi`)도 기록해 에너지 대비로 비교한다.

**0단계, 노트북 점검 (약 1분):**
```powershell
python agents\adaptive_buckets\aswiss\stud7\gpu\gpu_check.py --out agents\adaptive_buckets\aswiss\stud7\gpu\gpu_check.json
```
- 점검하는 것: PyTorch 로드, CUDA 빌드 여부, Blackwell(sm_120) 커널 지원, 실제 커널 실행.
- 위 망 크기들의 CPU 1스레드 대비 GPU 시간도 잰다. 결과 JSON을 보고 어느 부분을 GPU로 옮길지와 망 크기를 정한다.
- 걸릴 수 있는 곳:
  1. 저장소 기록상 노트북의 번들 PyTorch는 CPU 전용이다(`../../../../cpp_mccfr/README.md`).
  2. RTX 50 시리즈는 CUDA 12.8 이상 빌드(PyTorch 2.7 이상)가 필요하다.
  3. 이전에 pip 패키지 DLL이 Windows 애플리케이션 제어(WinError 4551)에 막힌 적이 있다. 막히면 WSL2(Ubuntu)에서 리눅스판 PyTorch로 돌리는 것이 우회로다. 이때 bash 실행기(`run_100m.sh`)를 쓴다.

**구현 순서 (점검 통과 뒤):**
1. MMD-GPU: 가장 단순하고 배치 이득이 크다.
2. ESCHER-GPU
3. ReBeL-GPU: 풀이를 텐서로 옮기는 일이 가장 크다.
- 각 단계마다 Kuhn·Leduc에서 CPU판과 같은 설정으로 결과가 같은 분포인지 확인하고, 7-stud 속도를 잰다.
