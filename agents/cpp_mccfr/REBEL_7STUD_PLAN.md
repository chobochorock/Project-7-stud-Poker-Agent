# 7-Stud ReBeL Implementation Plan

The executable Stud-Leduc oracle lives at
`D:\Experiment\Toy-Card-Game-Agent\rebel_stud_leduc.py`; its mechanism and
metrics are documented in `REBEL_STUD_LEDUC.md` beside it. Use its exact
exploitability and private-value targets as regression oracles before extending
the 7-stud resolver.

## Goal

Replace full-game table growth with repeated local solving in a public belief
state (PBS). The first target remains two-player, zero-sum, 5th-street onward;
H4 stays heuristic until the betting-game implementation is validated.

ReBeL is not a scalar value network over the visible board. At a public state
it represents both players' ranges and predicts one counterfactual value for
every private infostate:

\[
\beta=(p,\beta_0,\beta_1),\qquad
\hat v(\beta)\in\mathbb R^{|S_0|+|S_1|}.
\]

After observing action `a`, the acting player's range is updated by the search
policy likelihood:

\[
\beta_i'(s_i)\propto
\beta_i(s_i)\,\pi_i(a\mid s_i,\beta).
\]

Card compatibility and blockers are applied when normalizing the joint root
range. The opponent's actual hidden cards are never exposed to search.

## Search And Targets

At each sampled PBS, run a short CFR-AVG subgame. Terminal nodes use exact chip
payoff. Depth-limited leaves query the value network with the leaf PBS; their
values therefore change as the subgame policy changes the ranges.

For `T` search iterations, store the root infostate-value target

\[
y_v(\beta_r)=\frac1T\sum_{t=1}^{T}v^{\pi^t}(\beta_r)
\]

and optionally the average search policy target

\[
y_\pi(\beta_r)=\bar\pi^T(\beta_r).
\]

The policy network is only a CFR warm start. The value network is the required
component. During self-play, continue from a leaf generated by a randomly
selected search iteration and give one player a small exploration probability.

## Minimal Architecture

Reuse the current split between C++ data generation and PyTorch training.

- C++: game rules, compatible private-state particles, Bayesian range update,
  CFR-AVG public subgame, exact terminal values, replay generation.
- Python/PyTorch: batched value and policy inference and optimization through
  the existing IPC path.
- Value input: street, pot/stack, public cards, exact public betting line, and
  both range tensors.
- Value output: both players' values over a fixed private-state index.
- Policy output: legal-action probabilities per player/private-state index.
- Losses: pointwise Huber for value and probability MSE for policy.

Start with a fixed `K=64` private-state abstraction or a fixed particle index so
tensor shapes remain bounded. This is an engineering approximation: exact ReBeL
guarantees do not survive lossy bucketing, particle truncation, or imperfect
function approximation.

## Implementation Order

1. **Stud-Leduc oracle test**
   - Add exact PBS construction and Bayesian action update.
   - Use tabular leaf values and exact exploitability.
   - Require ReBeL search exploitability to decrease with search iterations.

2. **7th-street PBS solver**
   - Search from the exact public 7th-street state to terminal payoff.
   - Compare its policies and values with the existing exact seventh resolver.
   - This validates ranges, blockers, and CFR-AVG without a neural network.

3. **Train `V7`**
   - Sample 7th-street PBSs from self-play, solve them exactly, and fit their
     per-infostate value vectors.
   - Hold out deals and report value MAE plus policy regret, not only MSE.

4. **6th-to-7th ReBeL**
   - Solve 6th-street subgames to the 7th boundary using `V7` at leaves.
   - Store solved 6th root values and train `V6`.

5. **5th-to-6th ReBeL**
   - Repeat with `V6`, then run recursive 5th+ self-play search.
   - The current 30M/100M policy may initialize the policy network, but its
     regrets must not be treated as PBS value labels.

6. **Evaluation**
   - Stud-Leduc: exact exploitability.
   - 7-Stud: policy-LBR lower bound, heuristic pool, duplicate deals, and
     search-iteration ablations.
   - Compare equal C++ search node visits and wall time against MCCFR and the
     seventh resolver.

## Stop Conditions

Do not move from one street to the previous street unless:

- Bayesian posterior normalization and blocker tests pass exactly;
- value error improves over a constant/blueprint baseline on held-out PBSs;
- increasing local CFR iterations improves the measured policy metric;
- Stud-Leduc exact exploitability follows the expected downward trend.

The main risk is data generation, not network parameter count: every CFR
iteration evaluates many PBS leaves. Batch leaf queries before optimizing GPU
code.
